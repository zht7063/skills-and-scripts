# HTML、空间地图与验证

## 推荐的数据模型

新建页面可把事实与渲染分开，减少追加字符串导致不同区块失同步：

- `places`：稳定 ID、显示名、空间位置/精度、入口导航词、图片和来源。
- `routes`：稳定 ID、有序地点数组、交通段类型、日期或版本限制。
- `dayVariants`：按日方案、活动时间窗、可删减项、逐点停留预算、路线 ID。
- `state`：已选方案、自动/手动来源、当前地图路线。

既有页面不必为遵循模型重构；保留行为，集中修复受影响状态即可。

## 信息层次与速查

- 行程较长或用户要快速核对时，在头部给日期、时间窗、主要安排和跳转详情的简表，覆盖出发至最终返家。若“返家日期”与多城续程冲突，先确认，不能悄悄删掉续程。
- 速查表若展示所有备选，应明确“二选一/替代”；若展示当前选择，应随状态更新。调整时长后同时检查速查表，防止旧时间残留。
- 历史公告、证据与票价长说明可放附录或默认收起的 `details` 卡片，避免挡在路线操作前。目标日期未确认等直接影响选择的信息仍在选项旁简短保留。
- 折叠后测试点击摘要展开/收起、页内链接及直接带 hash 打开；链接指向折叠内容时，先展开祖先再滚动。打印若需包含附录，另行验证展开输出，不能假设浏览器自动处理。

## 地图与日程

- 增加方案时检查两个入口：日程方案选项和大地图路线选项；不能只更新日程预览而遗漏地图的独立按钮。对应路线共享稳定 ID 或显式映射，标题、节点顺序、耗时说明一致。地图浏览用于比较时不必改变已选日程，避免把浏览当作确认选择。
- 所有路线共享固定地点位置，切换只改变高亮、连线、顺序、旁栏说明。岛屿/湖岸/码头的空间关系和停靠流程图各有用途，不互相冒充。
- 绘图若未经地理坐标验证，标“示意、不按比例、非道路或航道”；不要给虚假比例尺。线路包含返程时注明它表示出行需求，不保证直达船。
- 日程放简洁地图预览，点击时先选择正确日期/方案再跳转。大地图显示同一数据的时间表，并有返回日程入口。
- 节点重复经过时显示可理解的顺序，避免数字挤出圆点；手机提供滚动/放大或文字替代入口，不能只有极小标签。
- 克隆 SVG 做预览时移除/重新命名内部 ID、事件属性及可聚焦元素；同步改写 `url(#...)` 引用。静态缩略图不要保留主图的数据选择器，防止后续切换误改缩略图。
- 自动跨日推荐不能覆盖手动方案。切换雨天方案时提示另一日同活动重复；保留用户最终控制。

## 离线交付

自包含模式使用内嵌 CSS/JS、内嵌许可范围内图片、SVG、系统字体，无 CDN、在线地图瓦片或运行时 API 前提。外部导航/购票/来源链接可保留，但提示联网。

若改动较多，源码与最终内嵌产物分开维护，最后构建单文件；无需复制整份大型 base64 HTML 进 skill。原项目照片不作为通用模板资产。

当地浏览器支持执行本地脚本才可交互。手机微信/文件预览可能不执行 JS，不保证“发文件即可完整运行”。需要手机实测才能声称某平台可用。PDF 是静态替代，无法切换路线；如果用户需要全部方案的 PDF，展开并输出各方案而非只打印当前选中项。发布网页需要用户授权，不因分享问题自动部署。

## 验收

先运行静态检查脚本，再针对改动执行浏览器检查：

1. 桌面和手机视口检查无全页横向溢出；宽表格及地图可在容器内滚动。检查顶部导航、标签、按钮命中区域和焦点。
2. 遍历方案按钮验证不同路线段数/顺序、日程和逐点预算随之变化，不能只改变选中颜色。
3. 验证自动推荐 → 手动覆盖 → 前日变化 → 恢复自动；检查重复景点提示。时间窗合计与候车/排队预算仍一致。
4. 浏览器实际加载图片，检查 `complete && naturalWidth > 0`；懒加载要先滚入或触发加载，避免把未触发当坏图。阻断网络后验证主体内容仍工作。
5. 检查 JS 运行错误、重复 ID、页内断链、SVG 引用，尤其在复制地图后。localStorage 失败应不影响本次使用。
6. 截图前禁用平滑滚动或使用 instant，待定位稳定后再截。只报告确实执行过的验证，不把 CSS 存在等同打印分页通过、不把桌面手机尺寸等同真机测试。

交付链接用绝对文件路径。更新既有文件后提醒刷新。将“已完成”“仍待目标日复核”“未实测平台”分别说明，避免模糊地称全部验证通过。
