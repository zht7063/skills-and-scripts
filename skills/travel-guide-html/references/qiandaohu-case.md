# 千岛湖案例复盘（整理于 2026-09-11）

这是流程案例，不是旅行资料库。以下日期、班次、时长都不应作为未来出行的已验证事实。

## 最终需求

两个人，杭州下班后高铁出发、当地打车；2026/9/29 晚抵达，9/30 和 10/1 两天游玩，10/2 下午或晚上去衢州，10/3 下午回杭州。输出真实图文、自包含 HTML、可切换地图和日程。原稿的“10/2 回杭州”后来被用户更正，案例应以此最终行程为准。

## 迭代中学到什么

1. **站点流程图不等于地图。** 最初七条游船线路用节点箭头表达顺序，用户仍觉得缺地图。后补有湖岸、岛屿与两处码头的空间示意图；所有线路共享位置，按钮高亮不同停靠顺序。示意岸线未经测绘，不能复用为真实航道。
2. **日程要与地图连起来。** 逐日文字时间线增加预览，点击进入大地图的对应日期；地图旁呈现当天安排并能返回。10/2 有散步/博物院两个替代方案。
3. **船线改变当天节奏。** 9/30 的梅峰单岛、中心四岛、中心三岛分别调整岛屿、午餐、休息与晚餐；选择不能仅改地图颜色。
4. **总时长和逐岛时间分别调查。** 未找到覆盖目标日的固定逐岛时长。2025 年当地新闻报道公交化运营，2023 年游记记录旧式停留时间，二者不得混用。页面明确数字为建议：单岛重点梅峰90–120分钟，多岛各点按体验分配。加总后四岛由5–7小时预算修正为6–8小时，说明细化会反过来修正总时间。
5. **多城续程会改变旧内容。** 新增衢州后补三段票候选、完整站名与换乘等待，同时更新住宿、离站时间和预算排除项。未来别再继承旧 README 的往返假设。
6. **次日留恢复时间。** 10/1 由“绿道＋咖啡＋天屿”改为上午二选一、午休、下午核心项目；多岛次日默认更轻松，手动可覆盖。雨天用博物院替代，并提示10/2不重复。
7. **缓冲需要删减规则。** 叫车、堵车、上山排队、下山和候位分别包含在时间窗中；迟到先删上午支线或夜逛，不能延长闭园时间来凑计划。
8. **离线文件分享有平台边界。** 图片脚本内嵌可减少依赖，但手机聊天预览可能禁用 JS。提供浏览器打开建议，不能保证所有手机预览支持交互。

## 后续迭代补充

- 头部增加从杭州出发、经千岛湖和衢州到最终回杭州的速查表。用户再次写成提前一天返家时先确认，最终保留原多城计划。
- 天屿日落由区域天文表辅助安排，晚餐随下山后移；因国庆清场和下山末班未确认，保留条件式夕照与提前下山规则。
- 博物院从较紧的核心参观预算扩为含互动、品鉴与排队的时间窗，同步提前雨天午餐和出发，并保留翌日赶车余量。数字不是固定参观时限。
- 2025 五一通告在同一假期改变 A 线组合。新增参考 B/C/D 后，把已有四岛方案括注“参考 A”，避免重复；不含梅峰的 E 线只作对照。历史线路均不能直接当作目标日商品。
- 用户发现新增参考路线只在日程入口可选，大地图独立按钮还未补齐；后补三个地图入口。以后新增方案要检查全部选择入口，而非只看当天预览是否联动。
- 将门票、普通船票、可选项目和机动分项，说明基础票/畅游票包含关系及历史价边界。长篇来源与票价说明改为默认收起卡片，保留跳转时自动展开。
